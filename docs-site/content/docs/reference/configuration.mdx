## Capture library

Set in the environment of the app process. The library reads them once, when CUDA initialises.

| Variable | Default | |
| --- | --- | --- |
| `CUDA_INJECTION64_PATH` | none | Path to `libwarpspan.so`. Setting it is what turns Warpspan on. |
| `NVTX_INJECTION64_PATH` | none | The same path again records [NVTX ranges](/docs/nvtx) as labels above each kernel. Read by NVTX on the first NVTX call. |
| `WARPSPAN_NVTX_MAX_LABELS` | `16384` | Most distinct NVTX label paths per process. Past it, new labels are recorded as `(more NVTX labels)`. |
| `WARPSPAN_SOCKET` | `/var/run/warpspan/warpspan.sock` | The agent's socket. Empty means don't send. Paths over 107 bytes are rejected. |
| `WARPSPAN_DEBUG_FILE` | none | Also write one text line per kernel here. `-` means stderr. |
| `WARPSPAN_QUIET` | | `1` turns off the library's log lines on stderr. |
| `WARPSPAN_DISABLE` | | `1` loads the library but does nothing. Use it for runs with Nsight Systems or `torch.profiler`. |
| `OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES` | | Become the profile's `service.name` and resource attributes, as in the OpenTelemetry SDKs. |

Without `OTEL_SERVICE_NAME` or a `service.name` in `OTEL_RESOURCE_ATTRIBUTES`, the service is `unknown_service:<executable>`.

## Agent

```sh
./bin/warpspan [flags]
```

| Flag | Environment | Default | |
| --- | --- | --- | --- |
| `--socket` | `WARPSPAN_SOCKET` | `/var/run/warpspan/warpspan.sock` | Socket the libraries connect to. |
| `--otlp-endpoint` | `OTEL_EXPORTER_OTLP_PROFILES_ENDPOINT`, `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://localhost:4317` | OTLP/gRPC endpoint. `none` turns export off. |
| `--otlp-header k=v` | `OTEL_EXPORTER_OTLP_HEADERS` | | gRPC metadata. Repeat the flag for several. |
| `--interval` | | `10s` | How often to export. |
| `--node-name` | `NODE_NAME` | | Added as `k8s.node.name` to every profile. |
| `--span-profiles` | | `grouped` | Per-span GPU profiles: `grouped` (about one row per span instead of one per kernel), `full` (every kernel of every span) or `off`. See [Span profiles and cost](/docs/span-profiles). |
| `--exemplars` | | `1` | In `grouped` mode, how many of the slowest spans per process per interval keep every kernel. |
| `--max-samples` | | `100000` | Most distinct samples (kernel × span × NVTX labels) per process per interval. A busy TensorRT app with spans and NVTX labels makes tens of thousands per second; lower `--interval` or raise this if spans show empty profiles. |
| `--version` | | | Print the version and exit. |

The endpoint's scheme picks the transport: `http://host:port` is plaintext, `https://host:port` or a bare `host:port` uses TLS. A path after the port isn't allowed. Each export has a 10 second timeout, and each round of exports has to finish within one interval (10 seconds at shutdown), so a hung Collector can't stall the agent.

## Limits the agent enforces

| Limit | Value |
| --- | --- |
| Message size | 60 KiB |
| Kernel name length | 2048 bytes (the library truncates longer names) |
| Samples per process per interval | `--max-samples` (100,000) with a span or NVTX labels; past that, kernels are counted under their bare name; 10% more and they go under `[other kernels]` |
| Samples per profile message | 15,000; more are split over several profiles, because Pyroscope rejects a whole profile above 16,000 by default |
| Connections | 1024 |
